## 概要

数字ディグリー記譜法（ナッシュビル・ナンバー・システム系）に基づくコード譜の DSL。Markdown 文書に埋め込み、ブラウザ上で次のことができる:

- ディグリー（ローマ数字）⇄ 実音コード名のタブ切り替え表示と、任意キーへの移調
- 曲中の転調（`[key: +1]` / `[key: F]`。セクション頭でもコード行の途中でも書ける）
- コードごとの歌詞・セクションラベル・強調色
- 和音の再生（キー・テンポ・拍子に追従）
- 譜面の PNG 画像コピー

## Markdown への埋め込み

Markdown 文書には **`:::` 単独のフェンス**でコード譜ブロックを埋め込む:

```
:::
---
key: G
---
1 3m7 4M7 5 | b7 1
:::
```

- 開き・閉じとも `:::`（コロン 3 つ以上）の行。言語名は書かない（このプラットフォーム専用のコード譜ブロック）。閉じフェンスのコロン数は**開き以上**が必要（CommonMark のフェンス規則に準拠。`::::` を `:::` では閉じられない）
- ` ``` ` フェンスは言語タグに関わらず通常のコードブロックであり、コード譜にはならない
- `:::` 直後の文字列は無視される（将来 `:::名前` 形式を別種のコンテナに使う可能性を予約）

### インラインコード譜（`:コード:`）

本文の途中には **`:` で囲んだ単一のコード記号**を埋め込める（例: `ここで :2m7: から 251 に入る`）:

- 内容は **1 つのコード記号のみ**（空白・`:` を含められない）。文法はブロックのコード（[トークンの定義 §1](#1-コード-chord)）と同一で、アクシデンタル・クオリティ・テンション・スラッシュベース・`@色` が使える。`%` / `NC` / `_` / グループはコード記号ではないため使えない
- 表示は**ディグリーのみ**（`<span class="chord-inline">IIm7</span>`。タブ・移調・再生は持たない）
- **平文フォールバック**: 内容が単一のコード記号としてパースできない場合（`:smile:` など）は記法として扱われず、そのままのテキストで表示される。エラーにはならない
- **誤爆防止**: 開き `:` の直前・閉じ `:` の直後が半角英数字の場合も記法として扱われない（時刻 `10:30:45` や比 `3:4:5` を保護）
- インライン記法のパースはホスト側（markdown.mbt フォーク）が行い、HTML 生成は本パッケージの [`inline_chord_html`](./api.md#inline_chord_htmltoken-string-string) が担う

## フロントマター

ブロックの**先頭にのみ**、YAML 風のフロントマターを置ける:

```
フロントマター = "---" 改行 フィールド行* "---" 改行
フィールド行   = フィールド名 ":" 空白* 値
```

- フロントマターは**省略可能**。置く場合は 1 行目が `---` で、閉じの `---` 行が**必須**。閉じが無い場合は UnclosedFrontmatter エラーとなり、**以降の全行がフロントマター内と見なされるため本文はパースされない**（「正しい行の継続」の唯一の例外）
- コロンの後の空白は省略できる（`key:G` も可）

| フィールド | 値 | 既定値 | 説明 |
|-----------|-----|--------|------|
| `key` | `A`〜`G` + 任意の `#`/`b`、短調は末尾に `m`（例: `C` `G` `F#` `Bb` `Am` `C#m` `Bbm`。v1.5） | `C` | コードタブ・再生の初期キー。AST 上は宣言の有無を保持し、既定値の適用は表示層が行う |
| `bpm` | 整数 20-400（4 分音符基準） | `120` | 再生テンポ |
| `time` | `1/2` `2/2` `2/4` `3/4` `4/4` `5/4` `6/4` `3/8` `6/8` `9/8` `12/8`（ホワイトリスト制） | `4/4` | 拍子。再生時のスロット長とベースの刻みに反映 |

- 未知のフィールドは InvalidFrontmatterField、不正な値は InvalidKey / InvalidTempo / InvalidTimeSignature エラー

### 短調のキー

`key: Am` のように、キー名の末尾に小文字の `m` を付けると短調になる(v1.5)。

**ディグリーの数え方は長調と同じ**: 数字は主音から数えた長音階の度数で、`m` などのクオリティは書いたとおりに付く。短調だから意味が変わる数字・記号はなく、変わるのは主音だけである。短調でよく使う 3・6・7 度は `b` を付けて書く。

```
:::
---
key: Am
---
| 1m b6 b7 1m |      ; Am F G Am
| 4m 57 1m % |       ; Dm E7 Am
:::
```

- 相対長調で書く従来の書き方(`key: C` で `| 6m 4 5 6m |`)もそのまま使える。両者は同じコード名・同じ音になる(書き手がどちらかを選ぶ)
- ディグリータブは数字どおり(`Im ♭VI ♭VII`)。日本語の理論書の短調の書き方と同じ
- コードタブの綴りは、主音の綴りから長調と同じ規則で解決する(key C#m の `b6` は `A`、key Ebm の `b6` は `C♭`)
- キープルダウンは、短調のブロックでは**短調の 12 キー**(`Cm C#m Dm E♭m Em Fm F#m Gm G#m Am B♭m Bm`)になり、移調しても短調のまま。♭/♯ トグルの ♯ 側は `D#m` `A#m`
- 転調指示: 相対(`[key: +3]`)は長調・短調を保つ(Am → Cm)。絶対は書いたとおり(`[key: C]` で平行調の長調へ、`[key: Am]` で短調へ)
- `M` や小文字の音名(`AM` `am`)は不正(InvalidKey)

## 基本構造

```
入力     = [フロントマター] 行*
行       = コード行 | セクションラベル行 | 歌詞行 | 転調指示行
コード行 = (コード | グループ | 小節線 | 反復 | NC | 空拍 | 転調指示)*
セクションラベル行 = "[" 名前 "]"
歌詞行   = ">" 断片*
転調指示行 = 指示+
指示     = 転調指示 | テンポ変更 | 拍子変更
転調指示 = "[" 空白* "key" 空白* ":" 空白* 転調値 空白* "]"
テンポ変更 = "[" 空白* "bpm" 空白* ":" 空白* 整数 空白* "]"     ; フロントマターの bpm と同じ(20〜400)
拍子変更 = "[" 空白* "time" 空白* ":" 空白* 拍子 空白* "]"      ; フロントマターの time と同じホワイトリスト
転調値   = 相対値 | 絶対キー
相対値   = ("+" | "-") 整数            ; 半音数 1〜11（0 と 12 以上は不可）
絶対キー = ("A"〜"G") ("#" | "b")? "m"?  ; フロントマターの key と同一文法（m = 短調。v1.5）
グループ = パート ("-" パート)+
パート   = コード | "_"          ; _ は空きパート（等分割の拍を空け、直前の響きを伸ばす）
反復     = "%"
NC       = "NC" | "N.C."
空拍     = "_"
```

### パースの基本方針

- **fail-fast はしない**。エラーのある行は結果から除外してエラーとして収集し、正しい行のパースは継続する（部分 AST + エラー列を返す）。ライブプレビューで 1 文字ごとの不完全入力に耐えるための設計
- エラーには**行番号**（元ソース基準、1-indexed）が付く。コード行由来のエラーには **position**（行内の 0-indexed 文字位置）も付く（フロントマター・歌詞行のエラーは行単位のため position なし）
- **空入力・空白のみの入力**は、行を持たない空の楽譜として正常に扱う（エラーではない）
- 空行は無視される（行番号のカウントには含まれる）

## トークンの定義

### 1. コード (Chord)

空白文字（スペース、タブ等）で区切られた文字列で、以下の構造を持つ:

```
コード = [アクシデンタル] ディグリー [クオリティ] [セブンス] [オルタレーション] [省略音]* [括弧内オプション] [スラッシュベース] [色アノテーション]
```

#### 構成要素

- **アクシデンタル**: `s` または `#` (シャープ。等価) | `b` (フラット)
- **ディグリー**: `1` | `2` | `3` | `4` | `5` | `6` | `7`
- **クオリティ**: `m` (マイナー) | `dim` (ディミニッシュ) | `aug` (オーギュメント) | `q` (4度堆積) | `5` (パワーコード。v1.4)
  - `q` はルートから完全4度を 2 つ積む(root, +5, +10 半音。Key C の `1q` → C・F・B♭)
  - `q` にセブンス・オルタレーション・括弧内オプションは付けられない(InvalidQuartalCombination エラー)。アクシデンタル・スラッシュベース・色は可
  - `5` はディグリーの**直後**の 5 で、ルートと完全5度だけを鳴らす(Key C の `15` → C5、`b75` → B♭5)。表示は `I5` / `C5`。`q` と同じく、セブンス・オルタレーション・括弧内オプションは付けられない(InvalidPowerChordCombination エラー)。アクシデンタル・スラッシュベース・色は可
- **セブンス**: `7` | `M7`（別表記 `maj7`。同じ AST になる） | `6` | `add` + Addディグリー
  - **パース優先順位**: `maj7` → `M7` → `7` → `6` → `add`（長い表記から先にチェック）
  - **Addディグリー**: `2` | `4` | `6` | `9` | `11` | `13`
  - セブンスの直後に再びセブンスがマッチする場合（`1M77` `17M7` `1M7M7` `1M7add9` 等）は DuplicateSeventh エラー
  - **メジャーセブンスを補う略記**(v1.4): `M9` `M11` `M13`(`maj9` なども可)は「メジャーセブンス + そのテンション」と読む(`1M9` = `1maj9` = `1M7(9)`、`4M13` = `4M7(13)`)。`M` / `maj` はメジャーセブンスの印なので、ここだけはセブンスを補う。括弧で書いた形と**同じ AST** になる
    - 略記の後にもう一度セブンスを書くとエラー(`1M97` は DuplicateSeventh)
- **オルタレーション**: `b5` (フラットファイブ) | `#5` / `s5` (シャープファイブ。v1.4) | `sus` + ディグリー (2/4/6 のみ)
  - 括弧外のオルタレーション（括弧内表記と併用可能で、両方 AST に保持される）
  - **`-5`**: ハーフディミニッシュの慣用表記。**`m7` の直後のみ** `b5` の別表記として受理される（`2m7-5` = `2m7b5` = `2m7(b5)`）。`-` はグループ区切りと衝突するため、それ以外の位置（`27-5` `2M7-5` `2m-5` 等）は従来どおりグループとして解釈される。グループの中では使えない（`2m7-5-1` は 3 コードのグループ。ハーフディミニッシュをグループに入れるときは `2m7b5-1` と書く）
- **テンション**: `b9` | `9` | `s9`/`#9` | `11` | `s11`/`#11` | `b13` | `13`（シャープは `s` と `#` が等価）
  - **括弧なしのテンション**(v1.4): テンションは、括弧に入れずにセブンス・オルタレーションの後ろへ続けて書いてもよい。括弧の中に書いたものと**同じ AST** になり、**表示はいつも括弧の中**に出る
    - `579` = `57(9)`、`2m711` = `2m7(11)`、`1M79` = `1M7(9)`、`169` = `16(9)`、`57b9#11` = `57(b9,#11)`、`57sus4b9` = `57sus4(b9)`
    - **セブンスは補わない**。`59` = `5(9)`(表示は `V(9)`)、`2m11` = `2m(11)`、`513` = `5(13)`。セブンスを入れるなら `579` `2m711` と書く(9 としか書いていないのに 7 が表示に現れると混乱するため。`M9` などの略記だけは別)
    - `b5` `#5` はオルタレーション、`b9` `#9` `#11` `b13` はテンション(`57b5` と `57b13` は数字で区別される)
    - 括弧も書けば、括弧なしのテンションが先に入る(`59(b13)` = `5(9,b13)`。同じテンションは 1 つにまとめる)
    - テンションの後ろにセブンスは書けない(`597` `59M7` は UnrecognizedToken、`579M7` は DuplicateSeventh)
    - シックスナインは `169` または `16(9)` と書く。スラッシュの `16/9` は受理しない(`/` はベース音で、9 はベースの度数にならないので InvalidDegree)
- **省略音（omit）**<a id="省略音omit"></a>(v1.6): `omit3` | `omit5`。その度数の音を鳴らさない(`1omit3` = C(omit3) は C と G、`17omit5` は C E B♭)
  - テンションと同じく、括弧に入れても(`1(omit3)` `1M7(9,omit3)`)、括弧なしで続けて書いても(`1omit3` `1add9omit3` `1omit3omit5`)よい。どちらも**同じ AST**(括弧内オプションの `omit`)になり、**表示はいつも括弧の中**(`Cadd9(omit3)`、ディグリー表示は `Iadd9(omit3)`)
  - 括弧なしの omit は、セブンス・オルタレーション・括弧なしのテンションの**後ろ**に書く(`1omit3sus4` は不可。`1sus4omit5` と書く)
  - 度数は 3 と 5 だけ(`omit7` などは InvalidOmitDegree)
  - 同じ度数を変える指定とは一緒に使えない: `omit3` と sus(sus は 3 度を置き換える)、`omit5` と `b5` / `#5`(ConflictingOmit)。違う度数どうし(`1sus4omit5` `17b5omit3`)は使える
  - パワーコード `5`・4 度堆積 `q` には付けられない(従来どおり InvalidPowerChordCombination / InvalidQuartalCombination)
  - 別表記の `no3` `(no3)` は受け付けない(InvalidTension / UnrecognizedToken)
- **括弧内オプション**: `(` + オプション + (`,` + オプション)* + `)`
  - **オプション**: テンション | オルタレーション | 省略音(v1.6)
  - 空の括弧 `()` はエラー、カンマの不正使用（先頭・末尾・連続）はエラー
  - **括弧の内側では空白を許容する**（`1M7(b9, s11)` は 1 つのコードトークン）
- **スラッシュベース**: `/` + [アクシデンタル] + ディグリー
  - スラッシュがある場合、ディグリーは**必須**（欠落は MissingBassDegree。`1/8` のように 1-7 以外の度数は InvalidDegree）
  - アクシデンタルは**オプショナル**
- **色アノテーション**: `@` + 色名（`blue` | `red` | `green`）
  - コードトークンの**末尾**にのみ置ける（スラッシュベースよりも後）
  - ブログ記事中で文脈上目立たせたいコードに使う**表示用アノテーション**（音楽的な意味は持たない）
  - 色名は小文字のみ。`blue` / `red` / `green` 以外はエラー

### 2. グループ（`-` で 1 スロットを共有）

`-` でコードを連結すると、複数のコードが**表示上の 1 スロット**を共有する（四分音符に対する八分音符のような分割のイメージ）:

```
6m7 3m/5 4m 2-5
1-2m7-5@red
```

（1 行目は最後のスロットを `2` と `5` が等間隔で分け合う。2 行目は 3 連結で、色は個別のコードに付く）

- 各パートは通常のコードとして完全にパースされる（色アノテーションも個別に付けられる）
- **空きパート `_`**（v1.2）: パートの位置に `_` を書くと、その拍ぶんを空きにできる。表示は空白（拍位置の間隔は保たれる）、再生は**直前の発音を持続**する（トップレベルの空拍 `_` と同じ意味論）。例: `5-_-5-6` は 4 等分の 2 拍目が空き — 3 拍目からコードに変化をつける書き方。先頭・末尾にも書ける（`_-5` = 前半は直前の響きのまま、後半から 5）
- 空のパート（`2-` / `-5` / `2--5`）はエラー。区切り文字だけのトークン（`---` 等）は 1 つの UnrecognizedToken になる
- 括弧の内側では分割しない
- **設計判断**: `-` をグループ区切りに採用したため、ジャズ記法のマイナー略記（`6-` = 6m）は**サポートしない**。マイナーは常に `m` で書く

### 3. 小節線 (BarLine)

`|` は小節区切りを表す。空白なしでもトークンを区切る（`1|4` = `1` `|` `4`）。

### 4. 反復記号 `%`

`%` は**直前のコードの反復**（同じコードが続くこと）を表す省略記号。独立したトークンで、空白なしでも区切られる（`1%` は `1` と `%`）。

```
| 1M7 % | 4 % |
```

（`1M7 1M7 | 4 4` と同じ意味）

- パーサは反復の解決（どのコードを指すか）を行わず、AST には `Repeat` トークンとして残る。表示はディグリー・コード両タブとも `%`
- `%` に色アノテーション等は付けられない

### 5. N.C.

`NC` または `N.C.` と書くと「コードなし」を表すトークンになる（表示は常に `N.C.`）。ブレイクやストップタイムに使う。

```
| NC 1 | N.C. 4 |
```

- 1 スロットを占有し、**歌詞を割り当てられる**（ストップタイムで歌う場面）
- 色アノテーション等の注釈は付けられない（`NC@red` はエラー）
- グループ（`-` 連結）の中では使えない

### 6. 空拍 `_`

`_` は**空の拍**を表すトークン。スロットを 1 つ占有するが、コードは表示されない。拍位置を明示したいとき（コードを伸ばす・歌詞だけ置く）に使う。

```
| 1 _ _ _ |
> ひ か り の
```

（`1` を 4 スロット分に伸ばすイメージ。空拍にも歌詞を割り当てられる）

- 空白なしでも区切られる（`1_4` は `1` `_` `4` の 3 スロット。ただし `-` に隣接する `_` はグループの空きパートになる — `5-_-5-6` 参照）
- **歌詞の割り当て対象**（`||` 由来の空セルは対象外）
- グループの中では**空きパート**として使える（[§2 グループ](#2-グループ--で-1-スロットを共有)。v1.2）

> **注**: コメント構文は無い。`#` はシャープ記号（`s` と等価）としてトークンの一部になる（開発中の初期案にあった `#` コメントは廃止した）。

## セクションラベル

`[名前]` を**単独行**で書くと、セクションラベルとして扱われる。中身はフリーテキスト（自動採番はしない）。

```
[Aメロ]
| 1M7 % | 4M7 5 |

[サビ]
| 4M7 5 | 3m7 6m7 |
```

- ラベル名には `#` を含む任意の文字が使える（`[サビ #2]` など）
- **例外**: 中身が小文字の `key` + コロンで始まる場合（`[key: +1]` など。正確には `空白* "key" 空白* ":"` のプレフィックス）はセクションラベルではなく**転調指示**（次節）として解釈される。大文字の `[Key: F]` は従来どおりセクションラベル。なお `[小文字識別子: 値]` 形式全体がディレクティブ予約領域のため、セクション名への使用は避けること（現状 `key` 以外の識別子は従来どおりセクションラベルとして表示されるが、将来のマイナーバージョンで意味が与えられうる — [予約トークン](#予約トークン将来拡張)・[api.md §4](./api.md#4-互換性の約束)）
- `[A] 1 4` のように同じ行に他のトークンがある場合はラベルではなく、通常のコード行として解釈される（`[A]` は `[` がディグリーとして不正なため InvalidDegree エラー）
- 表示は**白抜きの反転バッジ**（背景 = 本文の文字色、文字 = ページ背景色。ライト/ダーク両テーマで自動反転）
- AST では `sections: [{line, name}]` として行番号つきで保持される

## 転調指示（`[key: 値]`）

`[key: 値]` は、**この位置以降（文書順）のディグリーを新しいキー基準で解釈する**転調指示。値はフロントマターの `key` と同じ語彙で書ける:

- **相対**: `+1`〜`+11` / `-1`〜`-11`（半音数。`+0` や `+12` 以上は InvalidKeyChange）
- **絶対**: `A`〜`G` + 任意の `#`/`b`、短調は末尾に `m`（フロントマターの `key` と同一文法）

### 配置

**単独行**（セクションラベルと同格の第 4 の行種）と、**コード行内のインライントークン**の両方に書ける。意味はどちらも同じ:

```
[ラスサビ]
[key: +1]
| 4M7 5 | 3m7 6m7 | 2m7 5 | 1 % |
```

```
[Bメロ]
| 4 5 | 3m 6m | [key: +2] 4 5 | 3m 6m | [key: +2] 4 5 | 57 |
```

（上はラスサビ頭で半音上げ、下は 2 小節ごとに全音ずつ上がり続けるパターン）

### 意味論

- 相対指示は**現在のキーからの合成**（`+1` の後の `+1` は初期キーから計 +2）。効果は次の転調指示まで続く
- **キープルダウンによる移調は「初期キーの差し替え」**。選択キーと宣言キーのピッチクラス差 δ が譜面全体に一様に適用され、**文中の絶対キー指示にも δ がかかる**。2 つの不変量が成り立つ: (1) 実効キーのピッチクラス ≡ ソース上のキーのピッチクラス + δ、(2) 転調幅は保存される（移調しても曲内の転調構造は変わらない）
- **スペリング**: δ = 0 の絶対指示は原文の綴りを尊重する（`[key: C#]` は C# のまま）。相対指示と δ ≠ 0 の絶対指示は正準 12 キー表 `C, Db, D, Eb, E, F, F#, G, Ab, A, Bb, B`（キープルダウンの一覧と同一）で綴る
- **`%`・`_`・N.C. は実音固定**: 転調指示は「次に書いたコードから」効く。`%` は転調をまたいでも直前の響き（実音）を繰り返し、`_` は直前の発音を持続する
- 転調指示は**スロット・歌詞・再生時間を消費しない**（拍位置・グリッドの列・再生カーソルのセル番号は転調指示の有無で変わらない）

### 構文の細則

- 判定は「ブラケットの中身が `key`（小文字）+ コロンで始まるか」。**このプレフィックスに一致したら、値が不正でも必ず転調指示として扱い InvalidKeyChange エラーにする**（`[key: H]` がセクションラベルとして黙って表示される事故を防ぐ）。`[Key: F]`（大文字）は従来どおりセクションラベル
- 空白は `[`・`key`・`:`・値の前後で許容される（`[ key : +2 ]` も可）
- グループ（`-` 連結）の中では使えない（`1-[key:+2]5` は従来どおり InvalidDegree エラー）
- インラインの `[` は**トークンの先頭**でのみブラケット開始になる（`1[key:+2]` は従来どおりエラー）
- 未クローズ（`[key:+2`）は InvalidKeyChange。`key:` で始まらないブラケット（コード行中の `[サビ] 1 4` 等）は従来挙動を完全に保存する（InvalidDegree）
- **インライン転調を含む行が別のトークンのエラーで行ごと除外された場合、その転調指示も消え、以降のキー領域は「指示なし」として継続する**（[エラーハンドリング](#エラーハンドリング)の「エラー行は存在しないものとして残りを描画する」原則の帰結）

## テンポ・拍子の変更（`[bpm: 値]` / `[time: 値]`）

`[bpm: 値]` は**この位置以降のテンポ**、`[time: 値]` は**この位置以降の拍子**を変える指示(v1.3)。値の文法はフロントマターの `bpm` / `time` と同じ:

- `bpm`: 整数 20〜400(4 分音符基準)。不正な値は InvalidTempo
- `time`: `1/2` `2/2` `2/4` `3/4` `4/4` `5/4` `6/4` `3/8` `6/8` `9/8` `12/8` のいずれか。不正な値は InvalidTimeSignature

```
[Aメロ]
| 1 4 | 5 1 |
[bpm: 80]
[サビ]
| 4 5 | 3m 6m | [time: 2/4] 4 | [time: 4/4] 5 |
```

- 配置・空白・未クローズの扱いは転調指示と同じ(単独行でもコード行の途中でも書ける。`[ bpm : 90 ]` も可)。プレフィックス(`[bpm:` / `[time:`。小文字)に一致したら値が不正でも必ず指示として扱いエラーにする。大文字の `[Bpm: 90]` は従来どおりセクションラベル
- 転調指示と同じく**スロット・歌詞を消費しない**。「次に書いたコードから」効く(行末に書けば次の行から)
- 同じ位置に `[bpm: …]` を続けて書いたら、あとの指定が有効
- 表示: テンポは `♩ = 140`、拍子は `3/4` のチップ(転調チップと同じ位置・同じ見た目)
- 再生: [再生仕様](#再生仕様)を参照

## 歌詞行

コード行の**直後の行**に `>` で始まる行を書くと、空白区切りの断片が直前のコード行のスロット（コード / グループ / `%` / `N.C.` / 空拍 `_`）へ**左から順に**割り当てられる。表示は各コードの真下。

```
| 1M7 % | 4M7 5 |
> ひかりの _ さきへ ゆこう

| 6m7 3m7 | 2-5 1 |
> きみと あるく この-みち へ
```

- **完全にオプショナル**: 歌詞行が無ければコード行の書き方・表示は一切変わらない
- **`|` は区切り**(v1.7): コード行の小節線とそろえて `> きみと みた | そら いろ |` と書いてよい。`|` は空白と同じ区切りで、断片には数えない(`きみと|みた` も 2 つの断片)。「整える」は、歌詞行に `|` があればコード行の小節線の真下に置き直し、無ければ足さない(行頭の小節線は歌詞行に写さない)。エディタの色付けは小節線と同じ `bar`
- `_` 単独 = そのスロットには歌詞なし（1 つスキップ）
- 断片中の `_` は表示上のスペースになる（`sweet_home` → `sweet home`。断片を分けずにスペースを含めるための記法）
- **断片中の `-` は拍分割**（v1.2）: コード側のグループ `-` と同じ概念で、断片をスロットの等分割に割り付ける。`_-あいあい` は 2 等分の後半（4/4 なら 3 拍目）から歌詞が始まり、`うえ-_` は前半だけに置く（空きは `_` か空で書く）。コード・`%`・N.C.・空拍のどのスロットでも使える。このため歌詞にリテラルの `-` は書けない（従来もグループ上では分割記号だった）
- 断片がスロット数より**少ない**のは正常（残りは歌詞なし）。**多い**場合は TooManyLyricFragments エラー（先頭から割り当てた上でコード行の描画は維持される）
- グループ（`2-5`）への断片は、`-` でグループのパート数どおりに分割できる場合に各パートへ配られる（`この-みち` → `2` に「この」、`5` に「みち」。コードの実位置に揃う）。**パート数と一致しない拍分割**（例: `5-_-5-6` の上に `_-よう`）は他のスロットと同じ「スロット全幅の等分割」として置かれる — **歌詞とコードの分割数は一致していなくてよい**。`-` を含まない断片は先頭のパートにまとめて付く
- 歌詞行は**自由テキスト**であり、`#` などの記号もそのまま歌詞の一部になる
- 歌詞行の直前の行がコード行でない場合（ブロック先頭・空行やラベルの直後・歌詞行の連続・**直前のコード行がパースエラーで除外された場合**）は OrphanLyricLine エラー
- 転調指示の単独行の直後の歌詞行は、割り当て先スロットが 0 のため TooManyLyricFragments エラー（「歌詞を割り当てるスロットが直前の行にありません（歌詞行はコード行の直後に書きます。転調指示行には付けられません）」の専用メッセージ。小節線だけの行 `| |` に歌詞を付けた場合と同じ扱い）。歌詞はコード行の直後に書き、転調指示はその前の行かコード行内に置く
- コードタブ（実音表示）・任意キーへの移調でも歌詞は保持される

## 構文例

### 基本形

| 入力 | 意味 |
|------|------|
| `1` | ディグリー 1 |
| `3m` | ディグリー 3 マイナー |
| `b7` | フラット 7 |
| `#4` / `s4` | シャープ 4（どちらも同じ） |

### セブンス付き

| 入力 | 意味 |
|------|------|
| `5M7` / `5maj7` | ディグリー 5 メジャーセブンス（どちらも同じ） |
| `2m7` | ディグリー 2 マイナーセブンス |
| `47` | ディグリー 4 ドミナントセブンス |
| `36` | ディグリー 3 シックス |
| `4add6` `4add9` | add 系 |
| `3dim7` | ディグリー 3 ディミニッシュセブンス |
| `579` `2m711` `169` `57b9#11` | 括弧なしのテンション(v1.4。`57(9)` `2m7(11)` `16(9)` `57(b9,#11)` と同じ。表示は括弧つき) |
| `59` `2m11` `513` | セブンスなしのテンション(v1.4。`5(9)` `2m(11)` `5(13)` と同じ。7 は補わない) |
| `1M9` `1maj9` `4M13` | メジャーセブンスを補う略記(v1.4。`1M7(9)` `4M7(13)` と同じ) |

### オルタレーション（括弧なし・括弧あり両対応）

| 入力 | 意味 |
|------|------|
| `1sus4` `4M7b5` | 括弧なし表記 |
| `1(sus4)` `4M7(b5)` | 括弧あり表記（推奨） |
| `2m7-5` | ハーフディミニッシュの慣用表記（`m7` の直後のみ。`2m7b5` と同じ AST） |
| `1q` | 4度堆積（ルート + 完全4度 + 完全4度） |
| `57#5` `57(#5)` | シャープファイブ(v1.4。`s5` も同じ) |
| `15` `b75` | パワーコード(v1.4。ルート + 完全5度) |

### テンション付き

| 入力 | 意味 |
|------|------|
| `1M7(b9)` | 単一テンション |
| `2m7(b9,#11)` | 複数テンション（カンマ区切り。`s11` も同じ） |
| `1M7(b9, s11)` | 括弧内の空白は許容 |

### 混在・ベース音・色

| 入力 | 意味 |
|------|------|
| `1M7b5(b9)` | 括弧外 b5 + 括弧内 b9（両方 AST に保持） |
| `4M7(b5,b9)/b3` | ベース音つき |
| `#4M7(b5,b9)/b3@green` | 色アノテーションは常に末尾 |

## AST 定義

### TypeScript 型定義

```typescript
type ParseResult = {
  score: ScoreAST          // 部分 AST（エラー行は除外される）
  errors: ParseError[]     // 行番号・位置つきの構造化エラー
}

type ScoreAST = {
  meta?: ScoreMeta         // フロントマター（宣言時のみ）
  sections?: SectionLabel[]
  lines: Line[]
}

type ScoreMeta = {
  key?: string             // "C" | "G" | "F#" | "Bb" など
  bpm?: number             // 20-400
  time?: string            // "4/4" など
}

type SectionLabel = {
  line: number             // 元ソースの行番号（1-indexed）
  name: string
}

type Line = {
  line: number
  tokens: Token[]
  lyrics?: (string | null)[]  // スロットに左から割り当てた歌詞断片
}

type Token =
  | { type: 'Chord', chord: ChordNode }
  | { type: 'ChordGroup', chords: (ChordNode | { type: 'Hold' })[] }  // - 連結（1 スロット共有）。Hold = 空きパート _
  | { type: 'BarLine' }
  | { type: 'Repeat' }                            // %
  | { type: 'NoChord' }                           // NC / N.C.
  | { type: 'EmptyBeat' }                         // _（空の拍）
  | { type: 'KeyChange', change: KeyChange }      // [key: 値]（転調指示。スロットを消費しない）

type KeyChange =
  | { type: 'relative', semitones: number }       // -11〜-1, +1〜+11
  | { type: 'absolute', key: string }             // "F" "Eb" など（検証済みキー名）

type ChordNode = {
  accidental?: 's' | 'b'
  degree: '1' | '2' | '3' | '4' | '5' | '6' | '7'
  quality?: 'm' | 'dim' | 'aug' | 'q' | '5'   // '5' はパワーコード(v1.4)
  seventh?: Seventh
  alteration?: Alteration    // 括弧外のオルタレーション
  options?: ChordOption[]    // 括弧内のオプション
  bass?: BassNote
  color?: 'blue' | 'red' | 'green'
}

type Seventh =
  | { type: 'seventh', value: '7' | 'M7' | '6' }
  | { type: 'add', degree: '2' | '4' | '6' | '9' | '11' | '13' }

type Alteration =
  | { type: 'b5' }
  | { type: 's5' }           // #5(v1.4)
  | { type: 'sus', degree: '2' | '4' | '6' }

type ChordOption = Tension | Alteration | Omit

type Omit = { type: 'omit', degree: '3' | '5' }   // v1.6

type Tension =
  | { type: 'b9' } | { type: '9' } | { type: 's9' }
  | { type: '11' } | { type: 's11' }
  | { type: 'b13' } | { type: '13' }

type BassNote = {
  accidental?: 's' | 'b'
  degree: '1' | '2' | '3' | '4' | '5' | '6' | '7'
}

type ParseError = {
  kind: string             // "InvalidDegree" など
  message: string
  line?: number            // 1-indexed
  position?: number        // 行内の 0-indexed 文字位置
  token?: string
}
```

    }

}
```

## エラーハンドリング

パーサは fail-fast せず、**行単位でエラーを収集**する。エラーのある行は部分 AST から除外され、`errors` 配列に `kind` / `message` / `line` / `position` / `token` を持つ構造化エラーとして記録される。1 行に複数の不正トークンがあれば、その行から複数のエラーが報告される。

| kind | 発生条件 |
|------|---------|
| InvalidDegree | ディグリーが 1-7 以外（ルート欠落 `/3`、不正ベース度数 `1/8` を含む） |
| InvalidSeventh | 不正な add 度数（`1add5` 等） |
| InvalidTension | 括弧内の認識できない要素（`1(b8)` `1(foo)` 等） |
| UnmatchedParenthesis | 閉じ括弧の欠落（`1M7(b9`） |
| EmptyParentheses | 空の括弧（`1M7()`） |
| InvalidCommaUsage | カンマの不正使用（`1(,b9)` `1(b9,)` `1(b9,,s11)`） |
| InvalidColor | 不正な色名・色名欠落・色の後に構成要素（`1@yellow` `1@` `1@red/3` `1@RED`） |
| UnrecognizedToken | 認識できない文字列（`1x`、区切り文字だけのトークン等） |
| DuplicateSeventh | セブンスの重複（`1M77` `17M7` `1M7M7` `1M7add9`） |
| MissingBassDegree | スラッシュ後のディグリー欠落（`1/` `1/b`） |
| InvalidSusDegree | sus 度数が 2/4/6 以外（`1sus5` `1(sus11)` `1(sus)`） |
| InvalidOmitDegree | omit の度数が 3 / 5 以外（`1omit7` `1(omit1)` `1omit`。v1.6） |
| ConflictingOmit | omit と同じ度数を変える指定の組み合わせ（`1sus4omit3` `17b5omit5` `17(#5,omit5)`。v1.6） |
| UnclosedFrontmatter | フロントマターの閉じ `---` 欠落 |
| InvalidFrontmatterField | 未知のフロントマターフィールド |
| InvalidKey | 不正なキー名（`H` `g` `am` `AM` 等。短調の `Gm` は v1.5 から有効） |
| InvalidTempo | bpm が整数 20-400 以外 |
| InvalidTimeSignature | 拍子がホワイトリスト外 |
| TooManyLyricFragments | 歌詞断片がスロット数を超過（転調指示行など割り当て先スロットが 0 の行への歌詞は専用メッセージ） |
| OrphanLyricLine | 直前がコード行でない歌詞行 |
| InvalidKeyChange | 不正な転調指示（不正な値 `[key: H]` `[key: +0]` `[key: +13]`、値の欠落 `[key:]`、未クローズ `[key:+2` を包含） |

エラー行の除外は転調にも波及する: **インライン転調を含む行が別エラーで除外されると、その転調指示も存在しないものとして以降のキー領域が解決される**（[転調指示の構文の細則](#構文の細則)参照）。

## 表示仕様

1. **ディグリー表示の変換**: DSL の入力は変えず、表示層で変換する — ディグリーは `I`〜`VII`（ローマ数字）、`b` → `♭`、`s`/`#` → `#`、`maj7` → `M7`。ベース音・括弧内テンションも同様（`#4M7(b5,b9,s11)/b3` → `#IVM7(♭5,♭9,#11)/♭III`）
2. **コードスロットグリッド**: 各コード・グループ・反復・N.C.・空拍を**スロット**（グリッドの 1 マス）に置き、列数はスコア内の最大スロット数に揃える。行が違っても同じ位置のコード同士が縦に揃う（実譜面のシステム整列のイメージ）。小節線 `|` はスロットを消費せず、**スロット境界の縦線**として描画される。行頭・行末の `|` はそれぞれ開始・終止の縦線になる。列幅は内容に応じて広がる（`minmax(max-content, 1fr)`）ため、長いコードが `...` に切り詰められることはない。`-` グループは 1 スロットを等間隔で分け合う（拍位置の表現）
3. **タブ切り替え**: ブロックは「ディグリー」「コード」の 2 タブを持つ（ブラウザ風タブ: アクティブタブが下のパネルと連結して見える）。**デフォルトタブはディグリー**
4. **コードタブと移調**: キーに基づいてディグリーを実音コード名に変換して表示する（`key: G` で `1 → G`、`3m7 → Bm7`、`5/3 → D/B`）。スペリングはメジャースケールの**レター（C-B）単位**で解決するため異名同音が正しくなる（key F# の `7` は `E#`、key Bb の `b3` は `D♭`）。ただし DSL のアクシデンタルとの合成で**ダブル以上のアクシデンタル**になるときは、読みやすさ優先で正準 12 キー表の異名同音に綴り直す（key D♭ の `b6` は理論上 `B♭♭` だが `A` と表示 — 2026-07-21 改訂）。キープルダウンで**任意のキー**へ移調でき、一覧は 12 半音（`C, D♭, D, E♭, E, F, F#, G, A♭, A, B♭, B`。宣言キーが一覧と異名同音の場合はそのスロットを宣言の綴りで置き換える — `C#` は `D♭` の位置）。プルダウン横の **♯/♭トグル**で黒鍵 5 スロットの綴りを ♯ 側（`C# D# F# G# A#`）へ一括で切り替えられる（OFF で元の綴りへ。2026-07-21 追加）。**綴りの優先度は選択キー名が運ぶ**: 既定表と違う異名同音側の綴り（`C#`・`G♭` など）が選ばれているときは、相対転調・δ 適用後の絶対キー・ダブルアクシデンタルの綴り直しもその向きの正準表で綴る（`C#` 選択で `[key:+2]` → `D#`。既定綴りの `F#` 選択は従来どおり `+2 → A♭`）。プルダウンの意味は**初期キーの差し替え**であり、選択キーと宣言キーの差 δ は文中の転調指示（絶対キー含む）にも一様に適用される（[転調指示の意味論](#意味論)）
5. **エラー表示**: エラー行は元の行位置に行番号・位置つきメッセージ + ソース行として埋め込まれ、正しい行のコード譜は描画され続ける
6. **画像としてコピー**: 「画像コピー」ボタンで表示中のタブの譜面を PNG としてクリップボードへ（不可の環境ではダウンロード）。画像は貼り付け先を選ばないよう常にライトテーマ（白地）で書き出す
7. **記法チートシート**: 全記法を 1 画面にまとめたチートシート HTML を `chord_cheatsheet_html()` が提供する（新規ユーザー向けのヘルプ。表示場所は埋め込み側が決める — プレイグラウンドではエディタのヘッダの `?` ボタンから開く）
8. 色アノテーション・歌詞・セクションは両タブ・全キーで保持される。ウィジェットは上下を区切り線で囲われたブロックとして表示される
9. **転調バッジ**: セクション = **塗り**（白抜き反転）に対し、転調 = **アウトライン**（currentColor の枠 + 背景透過）の視覚言語で区別する（ライト/ダーク/PNG 白地書き出しのすべてで追加実装なしに成立する）。単独行は全幅の転調バッジ行（`.chord-modline`）、インラインは**対応する小節（次のコードセル）の上部に浮かぶチップ**（`.chord-mod`。セルの行内には置かず、absolute でセル上端の左に寄せる — 2026-07-13 改訂）として描画する。行末のインライン指示は**直前セルの上部右**（実譜面の段末の予告調号の慣習）、スコア末尾の宙吊り指示も同様に描画する（書いたものを黙って消さない）。**ディグリータブにも転調チップを出す**（宣言キー基準で解決した後のキーを実音タブと同じ構成で併記する — 2026-07-20 改訂。単独行は相対指示なら `key D♭ (+1)`、絶対指示は `key F`。セル上部のインラインチップは小節幅に収めるためキー名のみ `D♭`。綴りは実音タブと同じ正準表で、接頭辞は初期キーチップに合わせた小文字 `key`。key 未宣言のスコアは既定値 C 起点で解決する）。コードタブは解決後のキーで表示し、単独行は相対指示なら `Key D♭ (+1)` のように転調幅を併記（絶対指示は `Key F` とキー名のみ）、インラインは幅優先でキー名のみ。チップは `.chord-cell` を増やさない（再生カーソルのセル番号は不変）。**転調直後の小節（チップの付いた小節から次の小節線まで）では、ディグリータブの各コードに転調前のキーで読んだディグリーを `=V` のように薄く添える**（ピボット・コードの可視化。単独行の転調は次の行の最初の小節に効く。プルダウンの δ は新旧キーを同じだけ動かすので、この関係は移調不変）。再生中はカーソルが転調をまたいだ瞬間にチップが一瞬点灯する（`.chord-mod--playing`。クライアントランタイムが付与）。**フロントマターでキーを宣言したスコアは、転調がなくても冒頭に初期キーチップ**（単独行と同じ全幅 `.chord-modline`）を出す（ディグリータブは宣言の綴りに忠実な `key E♭` 形式、コードタブは実効キー = プルダウンの選択キーに追従する `Key F` 形式。key 未宣言・既定値 C では出さない — 2026-07-14 追加）

## 再生仕様

「▶ 再生」ボタンで、**表示中のキー**（キープルダウンの現在値）の和音を再生する。再生中は鳴っているスロットがハイライトされ、ボタンは「■ 停止」に変わる（再生し切ると自動停止。キー変更で停止）。**コードセルのタップでそのセルの開始拍から再生**できる（停止中 = 部分再生、再生中 = シーク。持続和音とカーソルは頭を切り詰めて残し、ベース・スタブの打音は開始拍以降のみ。空拍などカーソル対象外のセルは無反応 — 2026-07-14 追加。実装はクライアントランタイム側）。

拍の解釈は「**1 スロット = 1 小節**」（NNS の「1 ディグリー = 1 小節」の慣習と一致）。小節の長さは拍子（`time`、既定 4/4）で決まる:

| トークン | 音 |
|---------|-----|
| コード | **上声**（ルート・3度・5度 + セブンス/6th/add・テンション。sus は 3度置換、dim/aug/b5 反映）を 1 小節持続。**ベース音**（スラッシュ指定 or ルート）は**拍ごとに刻む**（4/4 なら 4 打） |
| グループ `2-5` | 小節を等分割して順に発音（2 連結なら半小節ずつ。ベースは各コードの頭で単発）。空きパート `_`（`5-_-5-6`）は直前の発音をその拍ぶん持続する（先頭の空きは前のスロットから持続） |
| `%` | 直前のコードを**再打鍵**（ベースの刻みも再開）。直前のコードが無い行頭の `%` は無音の 1 小節として時間を占有する |
| `_` 空拍 | 直前の発音を 1 小節分**持続**（ベースの刻みは継続。N.C. をまたいだ持続はしない） |
| `N.C.` | 無音の 1 小節 |
| テンポ変更 `[bpm: 値]` | 以降のスロットの速さを変える。スロット自体は消費しない |
| 拍子変更 `[time: 値]` | 以降のスロットの長さ(1 小節)とベースの刻みを、新しい拍子で決める。スロット自体は消費しない |
| 転調指示 `[key: 値]` | **時間に影響しない**（スロットを消費しない）。以降のスロットのディグリー → MIDI 変換を新キー基準にする。`%` の再打鍵と `_` の持続は**直前の響き（実音）をそのまま使う**ため転調をまたがない |
| 小節線・セクション・歌詞 | 時間に影響しない |

- テンポは `bpm:`（4 分音符基準。既定 120）。`[bpm: 値]` で途中から変わる。**`parse_to_playback` の拍の単位は「冒頭のテンポでの 4 分音符」**に固定し、テンポが変わった後の長さはその単位に換算して返す(受け取る側は従来どおり `60 / bpm` で秒に直すだけでよい)
- 拍子とベースの刻み: 4 分系（x/4）は 4 分音符ごと、2 分系（x/2）は 2 分音符ごと、**8 分系の複合拍子（3/8, 6/8, 9/8, 12/8）は付点 4 分のグループごとに「ずん・ちゃ・ちゃ」**（グループ頭にベースのルート、続く 8 分 2 つは上声和音の短い刻み = スタブ。6/8 なら 1 小節に 2 グループ = ずんちゃっちゃ ずんちゃっちゃ）
- ベースの音域は可聴性のため **E2〜E♭3** の窓に収める（低すぎる音はオクターブ上げ。例: key E♭ の `6` は C2 ではなく C3）
- スケジュール生成（ディグリー→MIDI・`%` の解決・拍割り付け）は `parse_to_playback(input, key)` が JSON で返し、クライアントは Web Audio の発音（三角波シンセ）とカーソル表示のみを行う（移調と同じ単一ソース原則）
- パースエラーのある行は描画と同様に再生からも除外される

## 予約トークン（将来拡張）

以下の小節線バリエーションは ChordPro grid 語彙を正として**将来のために予約**する。現行仕様での動作: `||` は 2 つの小節線、`%%` は 2 つの反復記号として解釈される。将来のバージョンで意味が変わる可能性があるため、使用しないこと。

`||`（複縦線）、`|.`（終止線）、`|:` `:|` `:|:`（リピート）、`|1` `:|2`（ボルタ）、`%%`（2小節リピート）

また、**`[小文字識別子: 値]` 形式のブラケット**（単独行・コード行内のインライントークンとも）は**ディレクティブ予約領域**とする（v1.1 の転調指示 `[key: 値]` がこの枠の最初の住人で、v1.3 でテンポ・拍子の変更 `[bpm: 値]` `[time: 値]` を足した）。予約領域への意味付与の条件は [api.md §4](./api.md#4-互換性の約束) を参照。セクションラベル名にこの形式を使わないこと。

## 設計判断メモ

- **`-` グループ採用によるトレードオフ**: ジャズ記法のマイナー略記（`6-`）は将来もサポートしない（`2-5` と曖昧になるため）。マイナーは常に `m`
- **`_` の四義**: コード行 = 空拍（スロット占有）/ グループ内 = 空きパート（等分割の拍を空ける。v1.2）/ 歌詞行の単独 `_` = スキップ / 歌詞断片中の `_` = スペース
- **色は 3 色固定**: 記事内の視覚言語を単純に保つ（筆者が記事ごとに「赤 = 主題」等の意味づけをする余地を残す）。色価はテーマ側の CSS で決まる
- **短調のキーの数え方**(v1.5): 「主音から長音階で数える」(`Am` で `1m b6 b7`)を採り、「自然短音階で数える」(`1m 6 7` で Am F G)は採らない。後者だと同じ `6` が長調と短調で違う音になり、書き手が数字の意味を切り替える必要がある。前者なら数字の意味は常に 1 つで、従来の相対長調の書き方とも共存できる
- **キー・変換・再生の音楽計算は MoonBit 側の単一ソース**。クライアント（JS）は表示と発音のみを担い、ロジックを二重実装しない
- **転調記法の却下案**（v1.1 検討時）: プレフィックスなしの `[+2]` / `[F]`（セクション名 `[A]` と衝突）、セクションラベルへの属性付与 `[ラスサビ +1]`（ラベルはフリーテキストという原則を壊す）、新しいシグル `^+2` 等（語彙を増やす）、フロントマターに転調表を書く案（記述位置と効果位置が離れる）、`%%` 的な転調反復略記、行レベルのみ・インラインのみへの限定。採用した `[key: 値]` はフロントマターの `key:` を角括弧に写しただけで、新しい語彙を増やさない
- **`%` を転調をまたいで実音固定にした理由**: `%` は「直前のコードの反復（同じ響きが続く）」であり、再生の `last_voicing` の挙動とも一致する（実装差分ゼロで表示・再生が一貫する）。転調後の同ディグリーを鳴らしたいときはコードを書き直す
- **δ の一様適用（プルダウン = 初期キーの差し替え）**: 文中の絶対キー指定に δ を適用しないと、移調したとき曲内の転調幅が変わってしまう。2 つの不変量「pc(実効キー) ≡ pc(ソースのキー) + δ」「転調幅の保存」で定式化した
- **転調前ディグリー（=V）の pc→ローマ数字表**は `I, ♭II, II, ♭III, III, IV, #IV, V, ♭VI, VI, ♭VII, VII`（pc 6 は正準 12 キー表が F# を採ることに合わせて #IV。それ以外はフラット側）
- **相対転調・移調後の綴りは正準 12 キー表**（`C, Db, D, Eb, E, F, F#, G, Ab, A, Bb, B`）で解決する。キープルダウンの一覧と同じ表を単一ソース（transpose.mbt）にして二重定義しない。綴りの確認結果: E `+1` → F、B `+1` → C、B `+2` → Db、F# `+1` → G、F# `+2` → Ab（フラット側を好む同表の性格どおり。レター音程算による理論綴り C#/G# 等は採らず、プルダウンとの一貫性を優先）
